# App Store listing

The texts for the App Store Connect listing, one folder per language: `en`, `ru`, `de`, `fr`, `es`, `ja`. They are pasted into App Store Connect by hand; no build step reads them.

## Files and limits

| File | App Store Connect field | Limit | Rules |
| --- | --- | ---: | --- |
| `name.txt` | Name | 30 | `SkyAtlas:` plus a localized descriptor (`SkyAtlas: Window Seat Guide`). |
| `subtitle.txt` | Subtitle | 30 | One promise, in the words people search with. |
| `keywords.txt` | Keywords | 100 | Comma-separated with no spaces after commas. Don't repeat words from the name or subtitle, because Apple already indexes those. No brand or competitor names (Wikipedia, Apple, Flightradar24, …). |
| `promotional-text.txt` | Promotional Text | 170 | Can be changed at any time without a new build. |
| `description.txt` | Description | 4000 | The first two or three lines appear before "more", so they have to carry the whole idea. Aim for about 1,200–2,600 characters. End with the honest line about estimated position and weather. |
| `whats-new.txt` | What's New in This Version | 4000 | Two to four lines. |

Characters are counted as Unicode code points, the way App Store Connect counts them, so each Japanese character counts as one. The trailing newline at the end of a file is not counted.

Run the script after every edit. It fails (exit 1) in these cases:
- a text is over its limit;
- a keyword repeats a word from the name or subtitle, is duplicated, or is a brand name;
- keywords have spaces around commas;
- `whats-new.txt` is not two to four lines;
- any file mentions pricing, Pro or subscriptions, or a claim the app cannot back ("unlimited", live or real-time tracking, satellite imagery, AR, "Wrapped", Letterboxd).

## Voice

- A companion for the window seat: calm, precise, a little poetic, like a good guidebook. The brand metaphor is "subtitles for the window" (`docs/vision/VISION.md` §9.2). Use no emoji.
- Second person, with the same form of address as the app's UI strings: ru «вы», de «Sie», fr «vous», es «tú». Name UI elements exactly as `src/i18n/locales/<lang>.ts` names them («Взлетели», „gestartet“, « décollé », «despegamos», 「離陸した」, and so on).
- Spanish follows the app's Spain vocabulary (billete, facturar, wifi).
- French uses no-break spaces (U+00A0) before `: ; ? !` and inside `« »`, the same as `fr.ts`.
- Russian keywords are written with «е» rather than «ё», because that is how people type searches.

## What the listing may claim

Every claim must be true of the build being submitted. When the app changes, check this table before touching the copy.

| Claim | Where it lives |
| --- | --- |
| The flight is prepared on the phone, with no account and no server | `src/core/offline/buildPackage.ts`, `src/core/offline/prepare.ts`. The social layer and Sign in with Apple stay off unless `EXPO_PUBLIC_SOCIAL=1` (`src/core/features.ts`). |
| About 9,300 places (peaks, volcanoes, ranges, deserts, seas, lakes, islands, rivers, glaciers, cities) | `assets/data/places.skydata` holds 9,343 places; see `scripts/data/README.md`. |
| The route goes around closed airspace, depending on the carrier | `src/core/route/airspace.ts` |
| Boarding-pass scan and Apple Wallet `.pkpass` import | `src/core/wallet/bcbp.ts`, `src/core/wallet/pkpassParser.ts`. They fill in the airports, date, flight number and seat, but not the departure time. |
| Which side, what minute, how far, how long in view; window advice and daylight share | `src/core/places/corridor.ts`, `src/core/places/visibility.ts`, `src/core/flight/windowAdvice.ts` |
| Wikipedia stories and Commons photos in the user's language where an article exists, otherwise English | `src/core/places/wiki.ts`; the UI marks the fallback (`place.inEnglish`) |
| Offline map of the route corridor | `src/core/map/offlineMap.ts` |
| Borders, Equator, tropics, polar circles, Date Line, sunrise and sunset, start of descent | `src/core/flight/moments.ts`, `src/core/geo/lines.ts` |
| Check-in reminder a day before (which window to ask for, and what it will show; skipped when the seat is known or neither side is worth it); an "Airborne?" notification about 15 minutes after scheduled departure, with a lock-screen "Took off" button | `src/core/flight/reminders.ts`, `remind.*` in the locale files, `src/navigation/notificationRoutes.ts` |
| Tapping an in-flight alert opens that place's card | `src/core/flight/alerts.ts` (`data.kind: "sight"`), `src/navigation/notificationRoutes.ts` |
| Three best alerts by default, up to six, or off | `src/core/flight/alerts.ts` (`max: level === 'more' ? 6 : 3`), `pickAlerts` in `src/core/flight/moments.ts` |
| GPS refinement in airplane mode | `src/core/flight/gps.ts` |
| Guess what's coming, audio guide, "I see it" (gold) | `src/core/flight/guess.ts`, `ui/screens/AloftScreen.tsx`, `ui/screens/PlaceScreen.tsx` |
| Country stamps, XP, levels, five ranks, 30 achievements, quiz, postcard | `src/core/game/` (`achievements.ts` has exactly 30), `rank.*` in the locale files, `src/core/ux/share.ts` |
| Four-minute demo flight at 20× speed | `src/core/offline/demo.ts` (`DEMO_SPEED = 20`) |
| No ads, no tracking | There is no ad SDK. The privacy manifest in `app.json` declares `NSPrivacyTracking: false` and no collected data. PostHog analytics (`src/core/analytics.ts`) and Sentry (`src/core/observability/sentry.ts`) do nothing unless `EXPO_PUBLIC_POSTHOG_KEY` or `EXPO_PUBLIC_SENTRY_DSN` is set at build time. If either is set, update the privacy manifest and the App Privacy answers in App Store Connect, and check that "No tracking" still holds. |

Keep these out of the listing:
- Pro, subscriptions and prices. Purchases are disabled in this release: `MONETIZATION_ENABLED` is false without a RevenueCat key.
- "Live flight tracking", "real-time flight data", "satellite imagery", "AR". Positions come from a model, refined by GPS.

## Open questions before submission

- `docs/vision/VISION.md` §9.2 records that the name "SkyAtlas" is already taken on the App Store, and that a rename decision is still open. The suffixed names here (`SkyAtlas: Window Seat Guide`, …) may be accepted as distinct names, but if the app is renamed, every `name.txt` and every mention in the descriptions has to change.
- The same section suggests hiding the fr, es and ja listings at launch. The texts are ready if they go live.
