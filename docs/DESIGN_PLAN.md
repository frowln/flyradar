# SkyAtlas — план работ по дизайну

*Составлено: 2026-08-10. Макеты направлений: `docs/design/directions.html`.
Этот документ фиксирует, как должно выглядеть продовое приложение и что для этого делается.*

---

## 1. Что фиксируем

**Направление: «Приборы» + коллекционный лист из «Атласа».**

Продукт живёт в двух режимах, и дизайн обслуживает оба разными средствами:

| Момент | Вопрос пользователя | Средство |
|---|---|---|
| Полёт | «Где я и сколько осталось» | Приборная точность: моношрифт, шкалы, волосяные линии, янтарь |
| Открытие | «Что это за место» | Коллекционный лист: номер, спецификация, печать страны |

Всё остальное — навигация, настройки, оплата — оформляется как приборная система и не претендует на внимание.

**Одна смелость на весь продукт:** дуга-шкала на экране полёта вместо привычной полосы прогресса. Больше нигде не рискуем.

## 2. Дизайн-система

### 2.1 Цвет

Заменяет текущий `theme/colors.ts` целиком. Синий (`#5E8BFF`) удаляется — он не несёт смысла и делает приложение похожим на все остальные.

```ts
// theme/tokens/color.ts
export const dark = {
  // Основания. Шаг яркости между слоями ≤ 12 %.
  bg:            '#0B0E11',  // почти чёрный, холодный, не #000
  surface:       '#12161B',
  surfaceHigh:   '#191E25',
  // Линии
  line:          '#242B34',
  lineSoft:      '#1A1F26',
  // Текст
  text:          '#E9EEF4',
  textMuted:     '#7C8797',
  textDim:       '#556070',
  // Единственный акцент: «сейчас / активно / открыто»
  accent:        '#FF9E3D',
  accentSoft:    'rgba(255,158,61,0.12)',
  // Только статусы, не украшение
  positive:      '#4ADE80',
  warning:       '#FBBF24',
  negative:      '#F87171',
  // Латунь — исключительно для коллекционных элементов
  collect:       '#C9A227',
};
```

**Светлая тема** строится не инверсией, а отдельным подбором: шаг яркости между слоями ≤ 7 %, акцент темнее (`#C46A00`), чтобы держать контраст на белом.

**Правила цвета:**
- Один акцент на экран. Если на экране два янтарных элемента — один из них лишний.
- Нейтральные подкрашены: в каждом сером есть след янтаря, чистого серого нет.
- Цвет несёт информацию. Декоративного цвета не существует.
- Градиенты запрещены везде, кроме скримов поверх фотографий.

### 2.2 Типографика

**Fraunces удаляется полностью — в нём нет кириллицы,** и все крупные заголовки на русском сейчас молча подменяются системным serif. Это первая правка, и она обязательна.

| Роль | Шрифт | Кириллица | Где |
|---|---|---|---|
| Дисплей | **Manrope** (600/700/800) | есть | Заголовки экранов, названия мест |
| Текст | **Inter** (400/500/600/700) | есть | Всё остальное |
| Данные | **JetBrains Mono** (400/500) | есть | Цифры, метки, координаты, IATA |
| Японский | **Noto Sans JP** (400/500/700) | есть | Подмена дисплея и текста в локали `ja` |

Три семейства плюс японская подмена — предел. Serif не вводим: коллекционность несут номер листа и печать, а не гарнитура.

> **Instrument Sans, стоявший здесь в первой редакции плана, отвергнут:** проверка глифов
> показала, что кириллицы в нём нет — та же ошибка, что и с Fraunces. Все кандидаты
> теперь проверяются `npm run check:fonts` до вёрстки, а не после.

**Шкала.** Обязательна проверка каждого шрифта на глифы всех шести языков до вёрстки — включая японский (для него ставится **Noto Sans JP**, остальные латиницу-кириллицу не покрывают его вовсе).

```
display-l   34/38  -0.02em   Instrument Sans 700
display-m   27/31  -0.02em   Instrument Sans 700
title       20/26  -0.01em   Instrument Sans 600
body-l      17/25            Inter 400
body        15/22            Inter 400
body-s      13/19            Inter 400
label       10/12   0.14em   JetBrains Mono 500, uppercase
data-l      34/34  -0.03em   JetBrains Mono 500, tabular-nums
data        16/20            JetBrains Mono 400, tabular-nums
data-s      11/14   0.02em   JetBrains Mono 400
```

`font-variant-numeric: tabular-nums` обязателен везде, где цифры меняются в реальном времени — иначе таймер и высота дёргаются при каждом обновлении.

### 2.3 Сетка и отступы

Шкала 4 pt. Разрешённые значения: **4 · 8 · 12 · 16 · 24 · 32 · 48 · 64**. Произвольных отступов нет.

- Поля экрана: 20
- Между блоками: 24
- Внутри блока: 12
- Внешний отступ всегда больше внутреннего.
- Радиус: 0 для линейных разделителей и ячеек, 12 для карточек, 999 для печатей. Вложенный радиус = внешний − зазор.

### 2.4 Глубина

**Теней нет.** На тёмном интерфейсе тень нелогична — источника света не существует. Иерархия строится тремя средствами: шаг яркости, линия, размер.

Единственное исключение — стеклянные панели поверх фотографии в пост-полётных экранах.

### 2.5 Движение

- Длительность: 160 мс (микро), 240 мс (переход), 400 мс (появление карточки места).
- Кривая: `cubic-bezier(0.2, 0, 0, 1)`.
- Появление карточки POI — единственная анимация со своим характером: карточка не выезжает, а проявляется с лёгким увеличением, как показание прибора.
- `prefers-reduced-motion` уважается: все анимации становятся мгновенными переходами.
- **Ни один контент не зависит от анимации.** Стартовая непрозрачность всегда 1.

### 2.6 Иконки

Линейные, толщина 1.5, размер 20 и 24, скруглений нет. Никаких эмодзи в интерфейсе — сейчас они есть на экранах достижений и лидерборда, это главный визуальный маркер «сделано на скорую руку».

## 3. Компонентная база

Строится до экранов. Каждый компонент — отдельный файл, покрыт стори-состояниями (норма, загрузка, пусто, ошибка).

| Компонент | Назначение |
|---|---|
| `Gauge` | Дуга-шкала полёта с делениями и стрелкой |
| `TelemetryRow` | Строка из 3 показаний с разделителями |
| `PlateCard` | Коллекционный лист места: номер, фото, спецификация, текст |
| `QuizBlock` | Викторина под карточкой (готовый `QuizCard` переносится сюда) |
| `CountryStamp` | Круглая печать страны с датой |
| `AtlasRow` | Строка указателя: номер, название, лидер-линия, дата |
| `StatCell` | Ячейка статистики |
| `Rail` | Нижняя панель подсказки «через N минут» |
| `TabBar` | Навигация, 3 вкладки |
| `Sheet` | Модальный лист |
| `EmptyState` | Пустое состояние — приглашение к действию, а не извинение |
| `ErrorBanner` | Что случилось и как починить |
| `Skeleton` | Загрузка |

## 4. Как должен выглядеть каждый экран

### Ядро полёта

**InFlight** — главный экран. Сверху дуга-шкала: маршрут как дуга, самолёт как стрелка, в центре крупно время до посадки. Под ней строка телеметрии из трёх показаний. Ниже карта в тёмной приборной раскраске с волосяным треком и точками мест. Внизу рельс подсказки: «через 4 мин · по левому борту». Ночью карта гаснет, дуга остаётся.

**POIDetail** — коллекционный лист. Фото на всю ширину, номер листа и категория поверх. Название крупно, координаты моношрифтом. Спецификация из трёх величин. Текст 50–70 слов. Внизу викторина. Кнопка «Сохранить в атлас» появляется после прочтения, не сразу.

**Home** — ближайший рейс как приборная карточка: IATA, обратный отсчёт, статус пакета. Ниже — история рейсов линейным списком без карточек. Градиенты и glow-орбы удаляются.

**AddFlight** — единственное поле ввода, крупно, моношрифтом. Сканирование посадочного — равноправная кнопка, не второстепенная. Состояния поиска показываются текстом статуса, а не спиннером.

**FlightSummary** — итог по прилёту: сколько открыто, какие страны, дистанция. Готовая карточка для шеринга собирается здесь.

### Коллекция

**Collection / WorldMap** — атлас стран сеткой из ячеек с кодами и счётчиками. Открытые — янтарь, закрытые — приглушённые. Карта мира с треками показывает накопление, а не текущий рейс.

**Profile** — позывной, ранг, уровень, три ключевых показателя. Ниже — сетка стран и блок «редкая находка» с процентом пользователей, видевших это место.

**Stats** — таблицы, не круговые диаграммы. Данные выравниваются по разрядам.

**Wrapped** — единственный экран, где разрешено отступить от системы: годовой итог делается как отдельный визуальный сюжет под шеринг.

### Остальное

**Onboarding** — три экрана, каждый показывает один реальный экран приложения, а не иллюстрацию. Последний — запрос уведомлений с честным объяснением, зачем.

**Paywall** — показывается на пятой карточке в воздухе, не на старте. Сравнение тарифов таблицей. Per-Flight $1.99 — первичная кнопка, годовой — вторичная.

**Settings** — сгруппированный список, никаких иконок-эмодзи.

**Browse** — поиск чужого рейса, тот же визуальный язык, что InFlight, но без телеметрии.

**FlightDetail / Referral / Leaderboard / Simulator** — приборная система без исключений. Leaderboard до этапа открытой соцсети остаётся честной заглушкой с описанием, что появится.

## 5. Правила, которые нельзя нарушать

1. Один акцентный цвет на экран.
2. Теней на тёмной теме нет.
3. Отступы только из шкалы 4 pt.
4. Эмодзи в интерфейсе нет.
5. Градиент только как скрим поверх фото.
6. Каждый шрифт проверен на глифы всех шести языков.
7. Цифры — только моношрифтом с `tabular-nums`.
8. Пустое состояние — приглашение к действию.
9. Ошибка говорит, что случилось и что делать.
10. Контент не зависит от анимации.

## 6. План работ

Порядок обязателен: система → компоненты → экраны. Обратный порядок даёт то, что есть сейчас.

### Этап 1 — Фундамент · 3–4 дня
- Удалить Fraunces, подключить Instrument Sans + Noto Sans JP
- Проверить глифы шести языков скриптом, добавить проверку в CI
- Переписать `theme/colors.ts` в токены, убрать синий
- Ввести `theme/spacing.ts`, `theme/motion.ts`, шкалу типографики
- Удалить все тени и градиенты из существующих стилей

**Готово, когда:** приложение собирается на новых токенах, ни одного хардкод-цвета в `src/` не осталось.

### Этап 2 — Компоненты · 5–7 дней
Собрать 13 компонентов из раздела 3 со всеми состояниями. Экраны пока не трогаем.

**Готово, когда:** каждый компонент отрисован в четырёх состояниях и проверен в обеих темах.

### Этап 3 — Ядро · 5–6 дней
InFlight, POIDetail, Home, AddFlight, FlightSummary — пять экранов, на которых держится продукт.

**Готово, когда:** полный сценарий «добавил рейс → летел → открыл 3 места → увидел итог» проходится на устройстве и выглядит как один продукт.

### Этап 4 — Коллекция · 4–5 дней
Collection, WorldMap, Profile, Stats, Wrapped.

### Этап 5 — Периферия · 4–5 дней
Onboarding, Paywall, Settings, Browse, FlightDetail, Referral, Leaderboard, Simulator.

### Этап 6 — Полировка · 3–4 дня
- Проход по всем экранам на маленьком (SE) и большом (Pro Max) устройстве
- Проверка на шести языках — русский и японский ломают вёрстку чаще всего
- Контраст: весь текст ≥ 4.5:1, крупный ≥ 3:1
- Тактильная отдача, звуки, `prefers-reduced-motion`
- Скриншоты для App Store

**Итого: 24–31 рабочий день.**

## 7. Критерии приёмки

Дизайн считается сделанным, когда выполнено всё:

- [ ] Ни одного хардкод-цвета вне токенов
- [ ] Ни одного отступа вне шкалы 4 pt
- [ ] Ни одной тени на тёмной теме
- [ ] Ни одного эмодзи в интерфейсе
- [ ] Все шрифты покрывают шесть языков, проверка есть в CI
- [ ] Все цифры моношрифтом с `tabular-nums`
- [ ] Обе темы проверены на всех экранах
- [ ] Контраст текста ≥ 4.5:1
- [ ] `prefers-reduced-motion` работает
- [ ] Проверено на SE и Pro Max
- [ ] Проверено на ru / en / de / fr / es / ja
- [ ] Экран полёта читается на минимальной яркости в тёмном помещении

## 8. Что нужно от вас

1. **Выбрать направление** — по макетам в `docs/design/directions.html`. Рекомендация зафиксирована в разделе 1, но решение ваше.
2. **Лицензии шрифтов.** Instrument Sans — OFL, бесплатен. Если хотите Suisse Int'l — это платная лицензия, ~€300 на приложение.
3. **Решить по фотографиям.** Направление «Иллюминатор» откладывается именно из-за них. Если появится своя фотобаза — оно становится доступным.
4. **Название ранга.** «Штурман» в макетах — заглушка. Система рангов должна быть придумана до этапа 4.

---

## 9. Что это меняет для пользователя

Сейчас приложение выглядит как аккуратная тёмная тема, которую можно встретить где угодно. После пересборки экран полёта будет читаться как показание прибора, а открытое место — как лист, который вы получили в собрание. Это две вещи, которых нет ни у одного конкурента, и именно они делают подписку за $19.99 в год объяснимой.
